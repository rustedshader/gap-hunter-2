# Test Reports Directory

This directory contains all generated test reports from the research-based testing framework. Reports are automatically generated during test runs and are excluded from version control via `.gitignore`.

## Directory Structure

```
tests/reports/
├── coverage/          # HTML and XML coverage reports
│   ├── fast-ci/      # Coverage from fast CI pipeline
│   ├── nightly/      # Coverage from nightly pipeline
│   └── full/         # Coverage from full test pipeline
├── e2e/              # End-to-end test result reports
│   └── YYYYMMDD_HHMMSS/  # Timestamp-based subdirectories
├── metrics/          # Test metrics and historical data
│   └── metrics_YYYYMMDD_HHMMSS.json
├── pytest/           # Pytest HTML reports
│   ├── fast-ci.html
│   ├── nightly.html
│   └── full.html
└── index.html        # Summary dashboard (auto-generated)
```

## Report Types

### Coverage Reports

**Location**: `tests/reports/coverage/`

**Description**: Test coverage analysis showing which lines of code are executed during tests.

**Formats**:
- **HTML**: Interactive reports with line-by-line highlighting (open `index.html` in browser)
- **XML**: Machine-readable format for CI integration (`coverage.xml`)

**Interpretation**:
- **Green lines**: Executed during tests (covered)
- **Red lines**: Not executed during tests (uncovered)
- **Yellow lines**: Partially covered (e.g., branch not taken)
- **Coverage percentage**: Ratio of covered lines to total lines

**Thresholds**:
- Fast CI pipeline: Minimum 70% coverage
- Full test pipeline: Minimum 80% coverage

### E2E Test Reports

**Location**: `tests/reports/e2e/`

**Description**: Detailed results from end-to-end tests using the golden dataset with LLM-as-a-judge evaluation.

**Contents**:
- Test execution results (pass/fail status)
- LLM judge scores (faithfulness, alignment, completeness)
- F1-Score for classification accuracy
- Detailed error messages and stack traces

**Interpretation**:
- **F1-Score**: Measures classification accuracy (target: ≥0.85)
- **Faithfulness Score**: Measures evidence grounding in original policy (target: ≥0.90)
- **Alignment Score**: Measures framework alignment with CIS MS-ISAC templates (target: ≥0.85)
- **Completeness Score**: Measures roadmap completeness (target: ≥0.80)

### Metrics Reports

**Location**: `tests/reports/metrics/`

**Description**: Historical tracking of test quality metrics over time.

**Format**: JSON files with timestamp-based filenames

**Contents**:
```json
{
  "timestamp": "2024-01-15T02:00:00Z",
  "test_phase": "nightly",
  "total_tests": 150,
  "passed": 148,
  "failed": 2,
  "skipped": 0,
  "duration_seconds": 1847.3,
  "coverage_percent": 82.5,
  "e2e_metrics": {
    "f1_score": 0.87,
    "faithfulness_score": 0.92,
    "alignment_score": 0.86,
    "completeness_score": 0.83
  }
}
```

**Interpretation**:
- Track trends over time to detect quality regressions
- Alert if any metric degrades by >5% compared to 7-day average
- Use `scripts/analyze_metrics.py` to visualize trends

### Pytest HTML Reports

**Location**: `tests/reports/pytest/`

**Description**: Self-contained HTML reports generated by pytest-html plugin.

**Contents**:
- Test execution summary (total, passed, failed, skipped)
- Individual test results with execution times
- Error messages and stack traces for failed tests
- Test duration breakdown

**Interpretation**:
- Quickly identify which tests failed and why
- Review execution times to identify slow tests
- Share reports with team members (self-contained HTML)

## Accessing Reports

### Local Development

After running tests locally, open reports in your browser:

```bash
# Coverage report
open tests/reports/coverage/fast-ci/index.html

# Pytest HTML report
open tests/reports/pytest/fast-ci.html

# Summary dashboard
open tests/reports/index.html
```

### CI/CD Pipelines

Reports are automatically uploaded as CI artifacts:

1. Navigate to the GitHub Actions workflow run
2. Scroll to the "Artifacts" section at the bottom
3. Download the `test-reports` artifact
4. Extract and open HTML files in your browser

## Generating Reports Manually

### Fast CI Tests (Unit + Integration)

```bash
pytest -m "unit or integration" \
  --cov=src \
  --cov-report=html:tests/reports/coverage/fast-ci \
  --html=tests/reports/pytest/fast-ci.html
```

### Nightly Tests (Golden Dataset + Adversarial)

```bash
pytest -m "golden or adversarial" \
  --cov=src \
  --cov-report=html:tests/reports/coverage/nightly \
  --html=tests/reports/pytest/nightly.html
```

### Full Test Suite

```bash
pytest tests/ \
  --cov=src \
  --cov-report=html:tests/reports/coverage/full \
  --cov-report=xml:tests/reports/coverage/coverage.xml \
  --html=tests/reports/pytest/full.html
```

## Report Retention

- **Local development**: Reports are gitignored and persist until manually deleted
- **CI/CD pipelines**: Reports are retained as artifacts for 90 days (GitHub default)
- **Metrics history**: Append-only log file tracks metrics indefinitely

## Troubleshooting

### Missing Reports

If reports are not generated:
1. Verify pytest plugins are installed: `uv pip list | grep pytest`
2. Check test execution completed successfully (exit code 0)
3. Verify output directories exist and are writable

### Coverage Too Low

If coverage falls below thresholds:
1. Review coverage report to identify uncovered code
2. Add unit tests for uncovered functions
3. Add integration tests for uncovered code paths
4. Consider if uncovered code is dead code that can be removed

### E2E Metrics Degraded

If E2E metrics degrade:
1. Review detailed E2E test reports for specific failures
2. Check if golden dataset policies have changed
3. Verify LLM model version hasn't changed
4. Review recent code changes that may affect quality
